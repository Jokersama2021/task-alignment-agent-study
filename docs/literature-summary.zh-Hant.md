# 文獻綜述摘要

本綜述延續工具型大型語言模型智能體的間接提示注入主題，關注合法使用者委託任務後，外部資料如何誘導越權行為。核心問題不只是模型是否辨識惡意句子，而是它會不會把低信任來源當成新目標，以及防禦是否仍讓原任務完成。本文已核讀五篇核心論文的主文、方法、實驗與限制，並另讀 Task Shield 的演算法及提示附錄。

InjecAgent 以固定工具回應測試注入後的動作，適合隔離內容對行為的影響；但它假設先前取用工具已成功，無法完整代表自主規劃過程。其 ASR-valid 只以有效輸出為分母，不能與包含格式失敗的結果直接相比。[4] AgentDojo 進一步讓智能體在有狀態的環境中選擇工具，以可執行條件分開驗證合法任務與攻擊目標，提供同時衡量效用及安全的基礎。[5]

WASP 把觀察推進到網頁工作流程，區分「行為已被帶偏」與「攻擊目標最終完成」。前者依賴軌跡判讀，後者檢查最終狀態；兩者落差提醒我們，攻擊未完成可能是智能體操作失敗，不能單憑低成功率認定防禦有效。[10] 因此，評測表必須交代成功條件、分母與合法任務能力。

防禦方面，Task Shield 以使用者任務為對齊目標，由模型抽取指令並判斷其貢獻，再回饋或攔截不對齊行為。[7] 它與只辨識危險詞語的規則不同，也保留對合理中間步驟的容許。然而，若抽取遺漏、評分被誤導，或模型把無關步驟說成必要準備，這道檢查仍可能失效，額外推論成本也須計入。

攻擊方面，AGENTVIGIL 透過變異、覆蓋回饋與種子選擇搜尋注入提示。[9] 這使固定攻擊集合上的防禦成績只能視為特定條件下的證據。優化過程、選定提示集合與未見任務的結果應分開報告，不能只挑最大的成功率作跨研究比較。

綜合而言，五篇工作形成「局部行為、狀態評測、網頁流程、任務對齊、動態紅隊」的互補關係。本作業選擇縮小復現 Task Shield 的模型抽取與貢獻評分組件，再以離線來源整理檢查軌跡、引用及最終產物。兩者共享可追溯證據的要求，但組件判斷、流程完成與端到端安全是不同主張，應各自保留限制。
