# 離線來源整理智能體的步數預算比較

## 任務與方法

研究任務是整理 Task Shield、AgentDojo 與 WASP 對工具型智能體提示注入防禦的不同證據與限制。輸入為三份已凍結的真實論文來源卡，含論文連結、PDF 雜湊、實際核讀頁碼、摘要及限制；卡片由 AI 輔助核讀整理，並非教師提供。執行程式只讀取本地卡片，沒有在執行時閱讀網頁或原始 PDF。

本次是標準函式庫實作的 deterministic fixture。固定策略先執行一次 `search_catalog`，依序讀取 S01、S02、S03，再以卡片短摘要和固定整合段落寫出 `final-brief.md`。搜尋實際對標題和關鍵詞做不區分大小寫的全部詞匹配；不相關查詢不會返回三份來源。`write_brief` 僅允許固定輸出路徑與已讀卡片構成的內容，未讀完、未知工具、額外參數或不合規路徑均停止。

## 唯一受控比較與結果

兩條件保持問題、query、來源卡、工具 schema、策略、簡報模板與 validator 不變，只將 `max_steps` 從 3 改為 6。一步等於一次工具呼叫，策略選擇及最終驗證不另外計步。

| max_steps | 實際 tool calls | 成功讀取 | 寫出 brief | 最終 validator |
|---:|---:|---:|:---:|:---:|
| 3 | 3 | 2 | 否 | FAIL |
| 6 | 5 | 3 | 是 | PASS |

3 步條件完成搜尋與前兩次讀取後停止，未以部分證據建立「完成」簡報。6 步條件在第 5 步寫入，保留 1 步餘額。失敗來源是固定五步流程無法容納於三步預算，並非來源不相關或模型理解失敗。每條件只執行固定策略，不計推論 token、模型延遲或 API 費用。

## 引用證據與品質核查

來源包 SHA-256 為 `8e4f6e4e78f079c323e162902389954c943a14ab685e0ed0914e2020ee32273f`。每次讀取保留完整卡片及其內容雜湊；trajectory 記錄前後狀態、工具結果雜湊及前一事件雜湊。寫入回條記錄實際 UTF-8 位元組數、簡報雜湊與已讀來源順序。這些記錄可核查「搜尋—三次讀取—寫入」的依賴，不能冒充真人閱讀證明。

獨立驗證器不匯入 runner，重新開啟檔案並重建狀態；6 步條件的全部檢查均通過。另在完成包的複本追加未記錄文字，驗證器以寫入雜湊不一致拒絕；將 S03 引用改為 S99 時，引用集合與卡片對應檢查也拒絕。這兩個負例只測試 validator，未加入比較表作為實驗因素。

## 限制與下一測試

本結果只說明六步足以容納這個固定的五次工具呼叫流程，不能推論增加預算普遍提升真實智能體表現。策略和摘述模板已寫定，沒有呼叫語言模型；來源卡的內容準確性仍依賴先前核讀，而非由程式自動證明。雜湊鏈可揭露檔案不一致，但不是抵抗完整證據包重寫的數位簽章。

下一測試可固定六步預算與同一 validator，加入主題相近但不回答問題的候選來源，檢驗搜尋與選擇規則的不足；該測試尚未執行。重跑方式見 `data/agent/README.md`，原始兩條件與完整檔案位於本目錄。
